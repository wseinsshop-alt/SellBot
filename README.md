## ✨ Что такое SellBot

SellBot — Telegram-бот для продажи цифровых товаров с расходуемым складом. Вы добавляете ключи или загружаете документы, а бот принимает оплату, закрепляет одну единицу товара за заказом и отправляет её покупателю.

**Одна покупка — один ключ или файл.** Проданная запись больше не участвует в новых продажах. Повторное получение возвращает тот же товар, сохраняя остаток на складе.

| Для покупателя | Для владельца |
|---|---|
| 🛍 Каталог с разделами, фотографиями и поиском | 📦 Загрузка и управление товарами |
| 👤 Личный профиль со всеми покупками | ⚙️ Настройки через Telegram |
| ❤️ Избранное и быстрое возвращение к товарам | 🎟 Промокоды и реферальные начисления |
| 💳 Баланс и история его изменений | 📈 Статистика продаж и остатков |
| 📥 Повторное получение купленного товара | 🔔 Уведомления о малом остатке |
| ⭐ Отзывы и запрос замены ключа | 💾 Резервные копии, экспорт и восстановление |

Весь исполняемый код находится в **`main.py`**. Пояснения, примеры и инструкции собраны в этом README; в исходнике нет поясняющих комментариев и docstring.

## 📦 Четыре файла для запуска

```text
main.py           Весь код SellBot
requirements.txt  Зависимости Python
config.env        Токен бота и ID владельцев
README.md         Описание и инструкция
```

После запуска рядом появятся рабочие данные:

```text
shop.db                      Текущая база магазина
backups/shop-2026-11-08.db    Пример дневной резервной копии
```

`shop.db` и `backups/` создаются автоматически. Сохраняйте их при обновлении. Папка `.venv/` появится при установке Python-зависимостей.

<a id="start"></a>
## 🚀 Запуск на Ubuntu 24.04

### 1 · Получите токен и свой ID

Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. Сохраните токен. Для доступа владельца нужен **числовой Telegram ID вашего личного аккаунта**.

### 2 · Заполните `config.env`

В конфиге только два поля:

```dotenv
BOT_TOKEN=
ADMIN_IDS=
```

После `BOT_TOKEN=` впишите токен от BotFather. После `ADMIN_IDS=` — свой числовой ID. Пример второй строки:

```dotenv
ADMIN_IDS=123456789
```

Несколько владельцев указываются через запятую: `ADMIN_IDS=123456789,987654321`. Все они имеют полный доступ. Кавычки и пробелы вокруг значений не нужны.

**Реальный токен заполняйте на сервере. На GitHub оставляйте конфиг пустым.** Остальные настройки магазина задаются через админку бота.

### 3 · Установите зависимости

Потребуется **Python 3.12 или новее**. На Ubuntu:

```bash
sudo apt update
sudo apt install -y python3 python3-venv
```

Загрузите четыре файла в одну папку, например `/opt/shop-bot`, и перейдите в неё:

```bash
cd /opt/shop-bot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
chmod 600 config.env
```

### 4 · Запустите SellBot

```bash
.venv/bin/python main.py
```

Откройте **личный чат** с ботом и отправьте `/start`. Если ID указан верно, появится кнопка **«Админ-панель»**.

| Команда | Действие |
|---|---|
| `/start` | Открыть главное меню и сбросить текущий ввод |
| `/cancel` | Завершить загрузку или отменить незаконченный ввод |
| `/fixtexts` | Для владельца: исправить старые шаблоны цен после обновления |

При ручном запуске процесс заканчивается вместе с терминалом. Для постоянной работы используйте [systemd](#hosting). На один токен и базу запускайте **один процесс**.

<a id="products"></a>
## 🛍 Создание первого товара

**Путь:** `Админ-панель → Разделы и товары → Добавить раздел → Открыть раздел → Добавить товар`.

Введите название, цену и описание через вертикальную черту:

```text
Лицензия | 150 | Персональный код активации после оплаты
```

В карточке товара настройте оформление и выдачу:

| Настройка | Что меняется |
|---|---|
| **Цена в ₽** | Стоимость новых покупок |
| **Название / Описание** | Текст карточки |
| **Фото товара** | Изображение в каталоге |
| **Закрепить / Порядок товара** | Положение в списке |
| **Срок** | Дата окончания в заказе и напоминание; `0` — без срока |
| **Тип выдачи / настройки** | **Ключи** или **Файл** |
| **Время замены** | Период запроса замены ключа; `0` — выключить |

Новый товар создаётся как **«Ключи»**. Для продажи документов выберите **«Файл»**. Товар станет доступен для покупки после загрузки соответствующего склада.

<a id="keys"></a>
## 🔑 Уникальные ключи

**Путь:** `Карточка товара → Тип выдачи / настройки → Ключи`, затем **«➕ Ключи»** в карточке.

Отправьте данные текстом или прикрепите TXT:

```text
FIRST-ACTIVATION-CODE
SECOND-ACTIVATION-CODE
THIRD-ACTIVATION-CODE
```

Каждая непустая строка — отдельная единица товара. Повторные строки в том же товаре отсекаются, включая ранее проданные записи.

| Параметр | Ограничение |
|---|---|
| Размер TXT | До 2 МБ |
| Строк за импорт | До 10 000 |
| Кодировка | UTF-8, UTF-16 с BOM или Windows-1251 |

### После оплаты

1. Бот берёт одну свободную запись.
2. Закрепляет её за покупателем и сохраняет заказ.
3. Отправляет ключ в личный чат.
4. Исключает запись из дальнейших продаж.

Повторное получение через **«Профиль → Мои покупки»** возвращает уже купленный ключ. Новая складская запись при этом не расходуется.

### Замена ключа

Задайте срок в **«Время замены»**. Покупатель сможет отправить запрос из своей покупки. Владелец получит уведомление с кнопками одобрения и отказа. Для замены нужен другой свободный ключ. Запрос замены не выполняется автоматически.

<a id="documents"></a>
## 📁 Уникальные файлы

**Путь:** `Карточка товара → Тип выдачи / настройки → Файл → Загрузить файлы`.

Отправляйте документы по одному. Каждый загруженный документ становится отдельной единицей склада. Можно последовательно отправить несколько файлов; `/cancel` завершит загрузку.

Например, для трёх персональных архивов:

| Загрузка | Продажа |
|---|---|
| `client-001.zip` | Уходит первому покупателю |
| `client-002.zip` | Уходит следующему покупателю |
| `client-003.zip` | Остаётся до следующей покупки |

Покупка получает **один свободный документ**. После продажи он больше не выдаётся новым заказам. Повторное получение возвращает тот же документ.

Повторная загрузка документа с тем же Telegram `file_unique_id` в этот товар не добавляет новую запись, даже если прежняя уже продана. Отправляйте именно **документы**, а не фотографии. Можно продавать ZIP, PDF, плагины, шаблоны и другие форматы, которые принимает Telegram.

Сам файл хранится в Telegram. В базе сохраняются его идентификаторы и связь с заказом. Применяются ограничения Telegram Bot API. При смене **Telegram-бота** документы потребуется загрузить заново: `file_id` привязан к конкретному боту.

<a id="stock"></a>
## 📦 Остатки и уведомления

Для ключей и файлов работает расходуемый склад. Когда свободных записей нет, новая покупка недоступна. Многократная продажа одной складской записи выключена, в том числе у товаров из старых версий с безлимитным режимом.

**Порог уведомлений:** `Товар → Тип выдачи / настройки → Порог остатка`.

- По умолчанию владельцы получают уведомление при остатке **3 и меньше**.
- Значение **0** выключает уведомления.
- Допустимый диапазон — от **0 до 10 000**.
- Проверка выполняется примерно раз в минуту, пока процесс работает.
- Уведомление отправляется один раз; после пополнения **выше порога** оно включается снова.

### Смена способа выдачи

Ключи и файлы учитываются отдельно. Если переключить товар, старые записи сохранятся в базе, но будут доступны для новых продаж только при выборе соответствующего типа. Файл не будет выдан как текстовый ключ.

Уже оформленные заказы сохраняют свой товар. Для ранее выставленных, но ещё не оплаченных счетов параметры фиксируются при сохранении оплаченного заказа — меняйте тип, когда по товару нет ожидающих оплат.

Срок из карточки используется для отображения даты и напоминаний. SellBot не отзывает уже скачанные файлы и не управляет сроком действия лицензии у её издателя.

## 👤 Меню покупателя

Главное меню остаётся компактным:

```text
🛍 Каталог          🔍 Поиск
👤 Профиль          🆘 Поддержка
📄 Документы        🌐 Язык
```

У владельца и сотрудников с административным доступом дополнительно отображается **«Админ-панель»**.

### Всё личное — в профиле

```text
👤 Профиль
├── 📦 Мои покупки
├── ❤️ Избранное
├── 💳 История баланса
├── 💰 Баланс / 🎁 Промокод
└── 👥 Реферальная программа
```

| Раздел | Для чего нужен |
|---|---|
| **Мои покупки** | Посмотреть заказы, повторно получить ключ или файл, запросить замену ключа |
| **Избранное** | Вернуться к сохранённым товарам; добавление и удаление — через сердечко в карточке |
| **История баланса** | Увидеть пополнение, покупку, резерв, возврат и бонус: сумма, причина, новый остаток |
| **Баланс** | Посмотреть средства и выбрать пополнение |
| **Промокод** | Активировать скидку или начисление на баланс |
| **Реферальная программа** | Получить личную ссылку и увидеть приглашения |

Кнопка **«Назад»** в покупках, избранном и истории баланса возвращает в профиль. Дублирующих кнопок этих разделов в главном меню нет.

Покупки показываются страницами по **8 заказов**, избранное — до **50 существующих товаров**. История баланса записывается с установки версии с журналом: прошлые операции задним числом не восстанавливаются.

Если каталог изменился, сохранённые покупки остаются доступны. Кнопка **«Купить повторно»** открывает текущую карточку и актуальную цену. Удалённый товар больше не продаётся.

<a id="payments"></a>
## 💳 Оплата и настройки

**Путь:** `Админ-панель → Настройки`.

| Настройка | Назначение |
|---|---|
| **Поддержка** | Ваш контакт для покупателей: `@username` или ссылка `https://t.me/username` |
| **Реф. %** | Процент начисления пригласившему; `0` выключает начисления |
| **Оплата звёздами** | Включение и выключение Telegram Stars |
| **₽ за ⭐** | Курс пересчёта рублей и Stars |
| **Platega** | Merchant ID и Secret для оплаты через провайдера |
| **Методы** | Выбор доступных способов оплаты |

Перед продажами укажите собственный контакт поддержки. В стандартных настройках сохранён пример контакта.

### Stars и рублёвый баланс

Цены и внутренний баланс отображаются в рублях. Stars пересчитываются по заданному курсу: по умолчанию **1,7 ₽ за ⭐**. Покупатель может пополнить баланс и оплачивать с него товары. При нехватке средств бот предлагает доступное пополнение или внешний способ оплаты.

### Карта и СБП через Platega

Откройте **«Platega»**, отправьте Merchant ID, затем Secret отдельным сообщением. В **«Методы»** можно указать `2,11` — СБП и карту. Доступность зависит от настроек аккаунта у провайдера.

Сохранение реквизитов не проверяет их действительность. Проведите пробный платёж. Проверка оплат работает в фоне; есть и ручная кнопка проверки. Настройки провайдера сохраняются в базе — дописывать конфиг не нужно.

Если оплаченный товар стал недоступен, штатный обработчик возвращает Stars либо зачисляет сумму на баланс в зависимости от способа оплаты. Для цифровых товаров учитывайте действующие правила Telegram по использованию Stars.

### Промокоды и приглашения

**Промокоды:** `Админ-панель → Промокоды → Добавить`. Пройдите вопросы бота: код, тип, значение, лимит и срок. Поддерживаются скидки и бонусы на баланс. Промокод можно отключить или удалить.

**Рефералы:** новый пользователь открывает бота по личной ссылке пригласившего. После оплаченной покупки начисляется установленный процент. По умолчанию — **10%**. Начисления видны в истории баланса. Обычный кэшбэк отключён.

## ⚙️ Управление магазином

| Раздел панели | Возможности |
|---|---|
| **Разделы и товары** | Каталог, цены, описание, фотографии, порядок и тип выдачи |
| **Ключи** | Просмотр складских записей ключевых товаров |
| **Промокоды** | Создание скидок и бонусов, лимиты и сроки |
| **Отзывы** | Оценки и комментарии покупателей |
| **Настройки** | Поддержка, курс, рефералы и оплата |
| **Админы / Роли** | Добавление сотрудников и назначение прав |
| **Рассылка** | Сообщение пользователям с поддержкой Telegram HTML |
| **Тексты** | Редактирование экранов и сообщений |
| **Статистика / Отчёты** | Общие показатели и продажи по периодам |
| **Журнал действий** | Изменения каталога, настроек и других данных |
| **Бэкап сейчас** | Создание локальной копии базы |
| **Экспорт базы данных** | Отправка копии базы владельцу в Telegram |

Раздела тикетов в панели нет. Кнопка поддержки покупателя ведёт по настроенному контакту. Запросы замены ключа приходят владельцу отдельными уведомлениями.

### Права сотрудников

Владельцы задаются в `ADMIN_IDS`. Через **«Админы»** добавляется числовой ID сотрудника, через **«Роли»** выбирается менеджер или поддержка. Новый сотрудник по умолчанию становится менеджером.

| Доступ | Владелец | Менеджер | Поддержка |
|---|:---:|:---:|:---:|
| Каталог, цены и склад | ✅ | ✅ | — |
| Просмотр отзывов | ✅ | ✅ | — |
| Ответ на сохранённое обращение из уведомления | ✅ | — | ✅ |
| Одобрение замены ключа | ✅ | — | — |
| Платежи, промокоды, тексты и рассылка | ✅ | — | — |
| Назначение ролей, журнал, бэкап и экспорт | ✅ | — | — |

Чтобы бот мог отправлять уведомления, сотрудник должен открыть личный чат и нажать `/start`. Проверка прав применяется и к старым кнопкам, и к незавершённым диалогам.

### Оформление сообщений

В редакторе сохраняйте переменные вида `{name}` и `{v}`: бот подставляет значения сам. `СБРОС` возвращает стандартный текст, `УДАЛИТЬ ФОТО` убирает изображение с поддерживаемого экрана. Фотографию товара можно изменить в его карточке.

Основные экраны поддерживают русский и английский языки. Дополнительные экраны этой сборки оформлены на русском.

### Отчёты и журнал

В **«Отчётах»** есть количество заказов и оборот за последние **24 часа, 7 и 30 дней**, топ-5 товаров и число покупателей с повторными покупками. Возвращённые заказы исключаются. Stars пересчитываются по текущему курсу; оплата с баланса учитывается один раз. Оборот не равен прибыли: себестоимость и комиссии не вычитаются.

**«Журнал действий»** хранит автора, объект, действие и дату изменений. Содержимое ключей и секреты в него не копируются. ID `0` обозначает системную операцию. Прежние значения всех полей журнал не хранит.

## 💾 Бэкап, экспорт и восстановление

### В чём разница

| Операция | Где оказывается копия | Что происходит с работающим магазином |
|---|---|---|
| **Автобэкап** | В папке `backups/` на VPS | Продолжает работать |
| **Бэкап сейчас** | Там же, обновляет сегодняшнюю копию | Продолжает работать |
| **Экспорт базы данных** | В личном чате владельца с ботом, файлом `shop.db` | Продолжает работать |
| **Импорт файла базы** | Содержимое файла заменяет текущую `shop.db` | Данные откатываются к состоянию из файла |

**Бэкап — сохранить копию на сервере. Экспорт — получить свежую копию в Telegram. Импорт — восстановить магазин из копии.**

### Что сохраняется

`shop.db` содержит пользователей, балансы, историю, каталог, ключи, записи файлов, покупки, промокоды, избранное, тексты, настройки и сохранённые реквизиты оплаты.

У фотографий и документов сохраняются **ссылочные идентификаторы Telegram**, не сами файлы. При восстановлении с тем же Telegram-ботом они используются повторно. База не является архивом с бинарным содержимым всех товаров.

**В копию базы не входят:** `main.py`, `requirements.txt`, `README.md`, `config.env` и папка `.venv/`. Токен Telegram и ID владельцев из конфига сохраните отдельно. Реквизиты провайдера, введённые через админку, находятся в базе.

### Как работает автобэкап

При первом фоновом проходе каждого дня **UTC** бот создаёт согласованную SQLite-копию. На работающем боте проверка запускается примерно раз в минуту. Если дневной файл уже есть, автоматическая проверка его не перезаписывает.

Пример:

```text
backups/
├── shop-2026-11-06.db
├── shop-2026-11-07.db
└── shop-2026-11-08.db
```

Хранятся последние **7 дневных файлов**. Более старые удаляются. Это семь сохранённых дат, а не семь копий за сегодня. Если бот не работал несколько дней, за эти даты файлов не будет.

Кнопка **«Бэкап сейчас»** обновляет файл **сегодняшней даты** текущим состоянием. При корректной остановке процесса сегодняшняя копия также обновляется. При аварийном завершении это не гарантируется.

Бэкап ничего не отправляет в Telegram. Он хранится на том же VPS и не спасает при полной потере сервера. Для отдельной копии используйте экспорт и сохраните файл на своём устройстве.

### Как сделать экспорт

1. Откройте `Админ-панель → Экспорт базы данных` под владельцем из `ADMIN_IDS`.
2. Бот создаст свежий снимок текущей базы.
3. Получите документ **`shop.db`** в личном чате.
4. Скачайте его на телефон или компьютер. Можно переименовать, добавив дату.

Экспорт не удаляет и не изменяет данные магазина. Он не берёт вчерашний файл из `backups/`: создаётся новая копия на момент нажатия. Папка бэкапов при экспорте не очищается и не обновляется.

Делайте экспорт перед обновлением, импортом или переносом на другой VPS. В базе есть личные данные, непроданные ключи и секреты — не публикуйте файл в репозитории и общих чатах.

### Как восстановить через Telegram

**Импорт заменяет базу целиком, а не добавляет записи к текущим. Действие выполняется после проверки файла, без отдельного шага подтверждения.**

1. Сначала экспортируйте текущую базу и сохраните её отдельно.
2. Завершите ввод или загрузку командой `/cancel`.
3. В личном чате с ботом под владельцем отправьте собственную копию `.db`, `.sqlite` или `.sqlite3` **документом**.
4. Дождитесь сообщения об успешном импорте.
5. Проверьте профиль, остатки, покупки и настройки оплаты.

Бот проверяет целостность и совместимость структуры файла до замены. После успешного импорта перезапуск для применения данных не требуется. Конфиг с токеном и владельцами не меняется.

Если бот выключен, восстановление можно сделать на VPS: остановите процесс, сохраните нынешнюю `shop.db` отдельно, положите нужную копию под именем `shop.db` рядом с `main.py` и запустите процесс снова. Сохраняйте права доступа пользователя, от которого работает служба.

**Важно при откате:** продажи, пополнения и другие изменения после времени снимка в нём отсутствуют. Реальные платежи при этом не отменяются. Сверьте их и проданные единицы перед возобновлением продаж, чтобы старый снимок не вернул на склад уже выданные товары.

<a id="update"></a>
## 🔄 Обновление и переезд

### Обновить существующего бота

1. Сделайте экспорт и отдельно сохраните `config.env`.
2. Остановите старый процесс.
3. Замените код и зависимости, сохранив прежнюю `shop.db` рядом с `main.py`.
4. Выполните установку зависимостей и запустите процесс.
5. Проверьте профиль и пробную покупку.

Миграции добавляют недостающие таблицы и столбцы автоматически. Старые данные не требуется загружать заново. Если прежняя версия продавала один общий файл многократно, новый склад уникальных документов нужно загрузить отдельно; уже сохранённые покупки остаются в истории.

Товары старых неподдерживаемых типов больше не продаются. Их записи сохраняются в базе; в админке можно выбрать ключи или файл. Для отката используйте прежний код и копию базы, сделанную до обновления, вместе.

### Перенести на другой VPS

Перенесите четыре файла сборки, свою `shop.db` и конфиг с **тем же токеном**. При необходимости перенесите `backups/`. Установите зависимости на новом сервере. Остановите прежний процесс перед запуском нового, чтобы один токен не обслуживали две копии.

<a id="hosting"></a>
## 🖥 Постоянная работа на VPS

<details>
<summary><b>Развернуть команды systemd для Ubuntu</b></summary>

Пример рассчитан на каталог `/opt/shop-bot`. В нём уже должны находиться файлы сборки и заполненный `config.env`. Если бот запущен вручную, сначала остановите его через `Ctrl+C`.

Создайте системного пользователя и установите зависимости:

```bash
sudo useradd --system --home /opt/shop-bot --shell /usr/sbin/nologin shopbot
sudo chown -R shopbot:shopbot /opt/shop-bot
sudo -u shopbot python3 -m venv /opt/shop-bot/.venv
sudo -u shopbot /opt/shop-bot/.venv/bin/python -m pip install -r /opt/shop-bot/requirements.txt
sudo chmod 600 /opt/shop-bot/config.env
```

Если пользователь уже создан, пропустите `useradd`. Затем создайте службу:

```bash
sudo tee /etc/systemd/system/shop-bot.service > /dev/null <<'UNIT'
[Unit]
Description=SellBot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=shopbot
Group=shopbot
WorkingDirectory=/opt/shop-bot
ExecStart=/opt/shop-bot/.venv/bin/python /opt/shop-bot/main.py
Restart=on-failure
RestartSec=5
UMask=0077
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/shop-bot

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload
sudo systemctl enable --now shop-bot
```

Если используете другой каталог, замените пути. База и папка бэкапов должны быть доступны на запись пользователю службы.

```bash
sudo systemctl status shop-bot --no-pager
sudo journalctl -u shop-bot -n 50 --no-pager
sudo systemctl restart shop-bot
sudo systemctl stop shop-bot
```

После замены кода, токена или списка владельцев перезапустите службу.

</details>

SellBot использует polling. Для запуска не нужен домен или входящий порт; нужен исходящий HTTPS к Telegram и, при использовании, к Platega.

<a id="faq"></a>
## 🧩 Частые вопросы

| Ситуация | Что проверить |
|---|---|
| Где покупки и избранное? | Откройте **Профиль** |
| Где история пополнений и списаний? | **Профиль → История баланса** |
| Почему нет кнопки админки? | В `ADMIN_IDS` указан ваш ID; после изменения конфигурации процесс перезапущен |
| Почему товар недоступен? | В выбранном типе остались свободные записи соответствующего склада |
| Куда делся проданный файл? | Он закреплён за заказом и доступен покупателю через профиль |
| Почему повторный файл не добавляется? | Этот Telegram `file_unique_id` уже есть в данном товаре |
| Как завершить загрузку файлов? | Отправьте `/cancel` |
| Почему не пришло уведомление об остатке? | Остаток уже отмечен как низкий; для нового уведомления пополните его выше порога |
| Где созданный бэкап? | В папке `backups/` на VPS; для файла в Telegram нажмите экспорт |
| Экспорт изменит магазин? | Нет, это новая копия текущего состояния |
| Импорт вернёт вчерашние покупки? | Он восстановит состояние на момент выбранной копии, включая тогдашние остатки |
| Появилась ошибка `Conflict`? | Токен используется другим процессом; остановите вторую копию |
| Изменения конфига не применились? | Нужен перезапуск процесса |

Сборка проверяется на временных базах и подменённых ответах Telegram. Реальные оплаты и выдачу ваших товаров проверьте пробной покупкой перед запуском продаж.
